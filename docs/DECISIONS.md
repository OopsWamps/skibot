# skibot 决策记录

2026-10-18 与产品负责人逐项确认。每条决策都回答过备选方案，此处只记结论。

## 一期决策

1. **定位**：面向大众滑雪者的产品。
2. **输入**：用户上传手机视频（朋友帮拍/固定机位），服务器离线批处理。不做实时、不做端侧处理。
3. **精度路线**：纯 2D 关节角度。视角分类作为前置步骤：侧面视频套矢状面规则，正面视频套额状面规则。单目 3D 提升与多机位 3D 明确不做（深度是猜的 / 与大众产品冲突）。
4. **一期形态**：CLI 管线打通"视频 → 关键点轨迹 → 角度 → 报告"。Web UI 后置到分析质量验证过关之后。
5. **姿态后端**：Sports2D 内置管线（YOLOX 检测 + RTMPose top-down，RTMLib 推理）。
   原计划 YOLO11-pose，因采用 Sports2D 作底座而升级为 top-down 方案（精度上限更高）。
6. **多人处理**：半自动。自动选择主轨迹 + 可改选。映射到 Sports2D 的 `person_ordering_method`
   （`greatest_displacement` / `largest_size` 等自动排序，`on_click` 即二期 Web 点选的原型）。
7. **一期指标**：五项，全部纯 2D 可算——
   侧面（矢状面）：屈髋角、膝弯曲角、躯干前倾角；
   正面（额状面）：膝盖内扣角、肩髋水平对齐。
   弯相位划分风险过高（切错相位则下游全错），留二期。
8. **参考值**：新手/中级/高级三档区间，初值从公开滑雪教学体系的定性描述转译，
   存于 `reference_values.toml`，数值需专业人士逐项确认后才可放行。留校准接口。
9. **输出**：标注视频（骨架+角度值，人脸默认打码）+ 结构化报告（JSON）。
   明确不做综合评分——参考区间未校准前，分数是放大不确定性。
10. **验证（放行标准）**：①关键点抽查：十几段真实视频每段抽帧核对骨架贴合、角度曲线无跳变；
    ②角度精度：20~30 帧人工量角对比，误差 ±5° 内。教练评审在包 UI 之前完成一轮。
    关键路径是收集真实滑雪视频素材（侧面+正面两组）。
11. **隐私**：人脸信息单独同意（PIPL 生物识别信息要求）、原始视频 7 天自动删除、
    存储加密、标注视频默认人脸打码（可关）。数据导出/删除流程等完整合规二期再做。
12. **上架与合规**（2026-10-18 补充）：项目暂不上架，不考虑商业因素。
    学术数据集的"仅限研究"条款不构成障碍；问题 11 的措施保留为实现默认值（打码默认开），
    许可审查和合规流程不再作为决策约束。

## 已知风险

- **左右腿交换（leg swap）**：Sports2D 官方 TODO 承认未修复。侧拍滑雪时两腿交叉遮挡是高发场景，
  验证阶段重点盯。
- **转弯偏离单一平面**：Sports2D 要求人尽量平行于运动平面拍摄；报告需注明该假设。
- **帧率**：低于 60fps 快动作精度下降；手机视频常见 30fps，侧面高速过弯可能运动模糊。
- **膝盖内扣角**：唯一无现成实现的指标，额状面 2D 近似，公式待真视频验证。
