# skibot 决策记录

2026-10-18 与产品负责人逐项确认。每条决策都回答过备选方案，此处只记结论。

## 一期决策

1. **定位**：面向大众滑雪者的产品。
2. **输入**：用户上传手机视频（朋友帮拍/固定机位），服务器离线批处理。不做实时、不做端侧处理。
3. **精度路线**：纯 2D 关节角度。视角分类作为前置步骤：侧面视频套矢状面规则，正面视频套额状面规则。单目 3D 提升与多机位 3D 明确不做（深度是猜的 / 与大众产品冲突）。
4. **一期形态**：CLI 管线打通"视频 → 关键点轨迹 → 角度 → 报告"。Web UI 后置到分析质量验证过关之后。
5. **姿态后端**：Sports2D 内置管线（YOLOX 检测 + RTMPose top-down，RTMLib 推理）。
   原计划 YOLO11-pose，因采用 Sports2D 作底座而升级为 top-down 方案（精度上限更高）。
6. **多人处理**：半自动。自动选择主轨迹 + 可改选。映射到 Sports2D 的 `person_ordering_method`
   （`greatest_displacement` / `largest_size` 等自动排序，`on_click` 即二期 Web 点选的原型）。
7. **一期指标**：五项，全部纯 2D 可算——
   侧面（矢状面）：屈髋角、膝弯曲角、躯干前倾角；
   正面（额状面）：膝盖内扣角、肩髋水平对齐。
   弯相位划分风险过高（切错相位则下游全错），留二期。
8. **参考值**：新手/中级/高级三档区间，初值从公开滑雪教学体系的定性描述转译，
   存于 `reference_values.toml`，数值需专业人士逐项确认后才可放行。留校准接口。
9. **输出**：标注视频（骨架+角度值，人脸默认打码）+ 结构化报告（JSON）。
   明确不做综合评分——参考区间未校准前，分数是放大不确定性。
10. **验证（放行标准）**：①关键点抽查：十几段真实视频每段抽帧核对骨架贴合、角度曲线无跳变；
    ②角度精度：20~30 帧人工量角对比，误差 ±5° 内。教练评审在包 UI 之前完成一轮。
    关键路径是收集真实滑雪视频素材（侧面+正面两组）。
11. **隐私**：人脸信息单独同意（PIPL 生物识别信息要求）、原始视频 7 天自动删除、
    存储加密、标注视频默认人脸打码（可关）。数据导出/删除流程等完整合规二期再做。
12. **上架与合规**（2026-10-18 补充）：项目暂不上架，不考虑商业因素。
    学术数据集的"仅限研究"条款不构成障碍；问题 11 的措施保留为实现默认值（打码默认开），
    许可审查和合规流程不再作为决策约束。

## 已知风险

- **左右腿交换（leg swap）**：Sports2D 官方 TODO 承认未修复。侧拍滑雪时两腿交叉遮挡是高发场景，
  验证阶段重点盯。（2026-10-19 EPFL 对账实测：尾部样本中仅 8%，主体区为 0，属真实但次要模式。）
- **转弯偏离单一平面**：Sports2D 要求人尽量平行于运动平面拍摄；报告需注明该假设。
- **帧率**：低于 60fps 快动作精度下降；手机视频常见 30fps，侧面高速过弯可能运动模糊。
- **膝盖内扣角**：唯一无现成实现的指标，额状面 2D 近似，公式待真视频验证。

## 验证进展（2026-10-19/20）

用 EPFL Ski2DPose 数据集（世界杯竞技素材，1982 帧人工标注、16 源视频 158 clip）做量化对账。

1. **图像级对账**（逐帧单图、无时域信息、最严苛）：关节误差中位 8.9px
   （人体尺度 2.9%，p90 8.2%）；屈髋角中位 2.7~3.0°、≤5° 占比 70~73%；
   膝弯角中位 4.7°、≤5° 占比 52%，但 ≤15° 达 81%。
2. **膝弯胖尾巴归因**（尾部 >15°，615 样本）：主因是深蹲姿态的 2D 压缩——
   gt 膝弯 >90° 在尾部富集 17.7 倍、>60° 富集 11.3 倍；视觉复核最差 6 帧中
   5 帧"模型与标注贴合"（几何极限，非管线 bug）。次因：人物过小（1.8 倍）、
   置信度低（1.6 倍）；leg swap 仅 8%。
3. **±5° 关的判读修正**（对决策 10）：膝弯误差是两态的——滑行/近直腿姿态下
   达标（≤5° 占比高、直腿反而保护性），深蹲相位下像素噪声被 arccos 放大成
   几十度。报告侧缓解：低置信度+深蹲帧标注"仅供参考"（待实现）；
   视频管线的时域平滑可再削尾部（试点 33%→44%）。
4. **参考值数据支撑**：竞技者五指标全程分布（`gt_angle_stats.json`）与
   `reference_values.toml` 占位区间明显错位（如膝弯中位 122° vs 占位
   advanced [145,162]）——根因是全程跨相位。（2026-10-20 批准并落地）
   advanced 档改用竞技 p25~p75 作"全程粗带"：屈髋 [66,135]、膝弯 [97,153]、
   躯干前倾 [22,49]、内扣 [94,153]、肩髋对齐 [4,15]；novice/intermediate
   维持占位待专业确认，"参考值未校准"水印保留。
5. **视频级对账**（完整管线：跟踪+插值+Butterworth，158 clip 全量）：
   关节误差中位 8.1px；屈髋中位 7.0°（≤5° 占 39%）、膝弯 6.0°（43%）、
   躯干前倾 2.1°（84%）、膝内扣 7.7°（37%）、肩髋对齐 5.8°（45%）。
   与图像级的差距做了归因分解（同一批标注帧）：裸 rtmlib 5.0° →
   Sports2D 管线 5.8°（坐标后处理+检测降频的开销）→ 锁定单轨迹
   6.7°（跟踪身份的开销）；帧对齐经 -2~+2 帧偏移验证无误。
   事后 6Hz 角度平滑无增益（标注帧间隔 ~1s、竞技动作快）。
   结论：竞技素材是管线的最坏情况；大众素材（近拍、慢速）预期开销
   更小。躯干前倾与肩髋对齐两项在全管线后仍稳稳达标。
6. **大众素材批量验证的执行链**（2026-10-20~21）：B站抓取 32 条 →
   人工筛 11 条 clean。跑通过程定下：①推理走 DML GPU——venv 装
   onnxruntime-directml（PyPI 直连不通，走清华镜像），rtmlib
   `tools/base.py` 本地补丁 `'cuda'→'DmlExecutionProvider'`（升级
   rtmlib 会丢），backend.py 显式 `--backend onnxruntime --device
   cuda`；模型推理 39 it/s vs CPU ~10，但多人场景瓶颈在 CPU 侧
   （GPU 利用率仅 25%）。②超时 900→7200s：长视频姿态+后处理真实
   需求（31045 帧 CPU 曾 3 条被杀）。③`--nb_persons_to_detect 8`：
   雪场人流密集素材曾检出 23 人，逐人推理+滤波拖垮管线；主角=
   画面最大且持续在场必在前 8。④坑：`--calculate_angles false`
   会让 sports2d 静默跳过整个后处理、trc 不落盘且无报错——禁用。
   ⑤长视频（>10000 帧）先 ffmpeg 降采样 15fps 再分析，帧数减半、
   角度曲线 15Hz 对 1~2s/弯够用，报告注明。
7. **素材形态修正**（2026-10-21 睿君纠偏）：教学/vlog 整条喂管线
   是错的——用户上传的是"单一主人公+连续滑行"。教学视频讲解段
   （站姿）稀释统计：11 条中有效帧率仅 5~52%。修正 = 段级清洗：
   trc 反查连续有效段（find_continuous_runs.py，≥10s）→ 目验
   是否真滑行 → ffmpeg 剪段重跑。首批命中 4 段（425s/353s/168s/
   87s，其中 2 段单人连续滑行）。"重训模型"不必：skibot 无训练
   环节，脏数据污染的是统计结论，入口清洗即可。
8. **教练评审（AI 模拟）完成**（2026-10-21，DECISIONS 10 的一次
   预演）：agent 模拟双板教学专家评审 novice/intermediate 参考值、
   指标定义与报告文案，产出 docs/coach_review_simulated.md。
   已落地：①knee_valgus verdict 文案降级为描述统计（其 advanced
   带与膝弯带 [97,153] 几乎重合 = 屈曲投影混淆的直接证据，停止
   "小于 180° 即内扣"式解读；更名留二期）；②报告并列带内百分位
   （band_percentile）；③assumptions 补坡度/相机水平系统偏差说明；
   ④视角门控复核已有（METRICS 注册表 + ambiguous 不出指标）。
   不落地：novice/intermediate 数值建议（原理推断、把握度中低，
   且现值与其差异在占位值粗误差内——留档供真人教练对照，
   "参考值未校准"水印保留）。复核发现：现行 novice/intermediate
   三项 sagittal 指标几乎无区分度、knee_valgus 方向反——占位值
   确需真人教练重定。二期待办新增：knee_valgus 更名、帧级视角
   分类、按相位拆分落带率。
9. **文献数值检索**（2026-10-21，睿君指令）：按水平分层的五指标
   完整角度表在公开文献中不存在——PSIA/CSIA 全为定性描述（多轮
   检索的阴性结果，与 AI 模拟评审判断一致）。最硬可引数据点 =
   Bon et al. 2021（9 名滑雪教练、20° 坡、弯末关节角：PT 外侧膝
   141.5/148.7°、髋 165/166°、内侧膝 114~117°），作 intermediate
   膝弯带的文献锚点写入 reference_values.toml 注释，带值不改
   （弯末 ≠ 全程中位，方向自洽）。内侧腿膝角比外侧低 25~30° 的
   发现佐证 select_side 口径正确。汇集见 docs/lit_angle_values.md。
   novice 档文献数值仍缺，维持占位待真人教练/本地采数。
10. **视角判定改帧级门控**（2026-10-21）：跟拍镜头缓慢左右转向时，
    整视频单一判定落入 ambiguous（正面/侧面票 0.4~0.6）→ 全盘不出
    指标——BV1Zr4y167oa 96% 有效帧却零指标即为实例，而跟拍正是
    用户上传的主要形态。改为：view.classify_view_frames 逐帧归属
    （votes==0 沿用"非正面即侧面"保守口径，防有效帧流失），
    metrics.compute_series 按 frame_view 逐帧门控（sagittal 只在
    侧面帧、frontal 只在正面帧），报告新增 mixed 判定（主导侧
    <60% 且另一侧成规模），mixed 下两侧指标都出、notice 声明投影
    误差。回归：Zr4y167oa 从 ambiguous/0 指标 → mixed/五指标全出
    （侧面帧 2797、正面帧 3572）。帧级视角分类（斜 45° 帧的归属
    精度）仍是二期项。
11. **一期收尾处置**（2026-10-22）：①第一轮 partial 素材 10 条
    （usable=1，待剪段）正式放弃——博主轮后滑行段样本 20+，
    边际价值低；判定记录保留在 reviewed.jsonl，二期扩样本可回看。
    ②环境可复现收尾：pyproject 补 imageio-ffmpeg 与
