# 二期规格：三维骨架分析与产品补齐

Status: ready-for-agent
日期：2026-10-23

## Problem Statement

用户上传一段朋友帮拍的滑雪视频，想知道自己的动作哪里不对。现在拿到五个角度，但它们量的是**图像平面上的投影角**，不是身体角度。

固定机位下，滑行者与相机的相对几何全程都在变：方位角随行进方向转，仰角随下滑距离变，人物在画面里还会变小。同一个动作换个机位，读数就变。参考区间也来自同一类机位下的二维标注，跨视频不可比。实测 EPFL 的 116 个 clip 里，髋部横向位置在标注帧间的跨度中位是 0.29 个画面宽，只有 11 个 clip 基本跟住人——也就是说，竞速素材本身就不是恒定机位。而 EPFL 的对账比的是"模型算出的二维角度"与"人工标的二维角度"，两边在同一平面上，证明的是姿态估计准，证明不了二维角度等于身体角度。

报告还把整段滑行压成一个中位数。一个弯内膝角可以摆动 25~40°，入弯、控制、出弯混在一起，参考带宽到没有判读力；教练评审的两项直接结论——novice/intermediate 的矢状面指标几乎无区分度、knee_valgus 的方向反——都源于此。

用户要的不只是数字，还有"看到自己的动作在空间里的样子"。

## Solution

把指标基准从二维投影迁到三维骨架。角度在骨架自身坐标中计算，固定机位不再进入读数；躯干前倾以重力方向为零基准，坡度不再伪装成前倾。

每段滑行拆成入弯、控制、出弯三个相位，报告按相位给出中位数、落带率和带内百分位，参考区间也按相位建立。

网页上原片（打码）与可旋转的三维骨架并排同步播放，相位着色，指标可叠加。两次上传按相位对比，跨机位可比。

三维精度靠三层验证建立：文献锚点校验指标定义与量级，自采多机位真值校验逐帧误差与跨机位一致性，现有真实素材校验物理一致性。素材超出验证包络时拒绝分析并给出重拍建议，不用一份不可信的报告代替。

## User Stories

1. 作为滑行者，我想上传手机视频后看到自己的三维骨架回放，这样我能从空间里看动作，而不是读一张表。
2. 作为滑行者，我想在播放时旋转骨架，这样我能从对判读最有利的角度看一个弯。
3. 作为滑行者，我想把原片（打码）和骨架放在同一时间轴上并排播放，这样我能核对骨架是否贴合自己。
4. 作为滑行者，我想调播放速度并逐帧查看，这样我能停在失去平衡的那一刻。
5. 作为滑行者，我想把屈髋、膝弯、躯干前倾分成入弯、控制、出弯三段，这样我知道问题出在弯的哪一段。
6. 作为滑行者，我想每一相位有各自的参考区间，这样"好"不再用一条混合了所有相位的带子来判。
7. 作为滑行者，我想在动画上看到相位颜色，这样数字能对应到具体时刻。
8. 作为滑行者，我想看到每个相位的中位数、落带率和带内百分位，这样我知道自己站在带里的什么位置。
9. 作为滑行者，我想按相位比较两次上传，这样我能判断练习有没有带来变化。
10. 作为滑行者，我想对比页明确标出哪些指标不可比，这样我不会把换机位误读成进步。
11. 作为滑行者，我想在报告页改选被分析的人，这样画面里同行的人不会被当成本人。
12. 作为滑行者，我想任务列表在服务重启后还在，这样长队不会丢。
13. 作为滑行者，我想明显拍废的视频在上传时就被拒绝，这样我不必等一小时才发现。
14. 作为滑行者，我想被拒绝时看到原因和重拍建议，这样我知道下一次该怎么拍。
15. 作为滑行者，我想在三维重建不可靠时整份报告不出，这样我不会看到系统自己都不信的数值。
16. 作为滑行者，我想知道验证过的适用条件（坡度、机位距离、分辨率、光照），这样我知道自己的素材是否在范围内。
17. 作为滑行者，我想人脸默认打码，这样我可以放心分析自己的视频。
18. 作为滑行者，我想导出的动画只有骨架、不含画面纹理，这样分享动作不额外暴露外观。
19. 作为教练，我想指标定义与生物力学口径一致（三维关节角、重力参考的躯干前倾），这样数值能和文献对照。
20. 作为教练，我想弯末的髋、膝角度落在文献动捕值的容差内，这样我能信任数值的量级。
21. 作为开发者，我想有一个纯的二维到三维提升适配器，这样换模型不用动评估流程。
22. 作为开发者，我想一次评估同时产出报告、相位数据和动画数据，这样报告与动画出自同一次计算。
23. 作为开发者，我想报告能区分"没有数据"与"数据正常"（相位条目为 null 并带原因），这样缺相位不会被读成 0。
24. 作为开发者，我想离线多机位工具能从合成相机还原已知三维点，这样标定与三角化在实地拍摄前就被验证。
25. 作为开发者，我想人工标注的换刃时刻产出边界误差报告，这样切分是按数字放行或拒绝的。
26. 作为验证者，我想先做文献锚点校验，这样指标定义错误在实地拍摄前就被排除。
27. 作为验证者，我想多机位素材覆盖固定远景机位、跟拍和斜角，这样验证的不是实验室条件。
28. 作为验证者，我想看到跨机位一致性（同一趟、两个方位角、相位中位数差 ≤3°），这样机位无关是被证明的，不是被假设的。
29. 作为验证者，我想在现有 20 多段真实视频上跑物理一致性检查（骨长恒定、脚不穿雪面、关节不反折、遮挡处不跳变），这样泛化失败能低成本暴露。
30. 作为维护者，我想保留二维管线作为姿态估计的回归对照，这样三维迁移不会悄悄降低关键点质量。
31. 作为滑行者，我想深蹲相位的膝弯条目继续带"2D 投影放大误差"的说明，直到三维验证证明该误差消失，这样旧问题不会被新管线掩盖。
32. 作为滑行者，我想在真人教练确认参考值前一直看到"参考值未校准"水印，这样占位值不会被当成结论。
33. 作为滑行者，我想肩髋对齐拆成横断面旋转与冠状面倾斜两个数，这样我能分清是转体还是侧倾。
34. 作为滑行者，我想看到三点夹角的辅助量，这样我能用教练熟悉的说法核对主指标。
35. 作为验证者，我想验收按相机方位角分层，这样好的平均值不会掩盖某个方向的坏结果。
36. 作为滑行者，我想动画标注数据来源与误差量级，这样我不会把回放当成精确测量。

## Implementation Decisions

### 指标基准

- 五项指标迁到三维骨架坐标计算。二维管线和现有 EPFL 对账工具保留，角色改为姿态估计的回归对照与外部效度参考，不再作为指标的最终基准。
- 主指标按 ISB / Grood–Suntay 关节坐标系（JCS）定义：
  - 屈髋角：骨盆–股骨 JCS（股骨绕骨盆 Z 轴）；教练可读的"躯干–大腿"夹角作为辅助量另列，两者不可互换。
  - 膝弯曲角：Grood–Suntay，θ = 180 − arccos((v_thigh·v_shank)/(|v_thigh||v_shank|))，完全伸直为 0°。
  - 膝内扣角：JCS knee abduction（cos β' = e1·e3；右腿 β = β' − 90°，左腿反向）。KVA 2G/3G 只作对照并注明投影平面。
  - 躯干前倾：重力矢状面与冠状面两个分量，另报坡面法向版本（signed θ_slope = θ_gravity − β）。
  - 肩髋对齐：拆成横断面 H-Ssep（ψ = atan2((h_p × s_p)·u, h_p·s_p)）与冠状面 thoraco-pelvic obliquity 两个数，不合成一个指标。
- 五项指标因此变为六项。三点夹角只作教练可见的辅助量，不作主判断。
- 定义必须在实地采集前冻结，并在 ADR 里写明 marker/segment 方案、零点、符号与坐标系。冻结后改定义等于重标真值。
- 视角门控取消：所有帧都参与五项指标计算，视角分类降级为质量提示。mixed 视角的逐帧归属特例随之简化，帧级视角归属仍保留用于质量统计。

### 三维提升

- 运行时输入仍是单目视频：二维关键点 → 三维骨架。多机位只用于离线真值。
- 提升作为纯适配器接缝：输入 Halpe-26 二维关键点，输出每帧 26 个三维关节（root-relative）与可见性/置信度。接口固定，模型可替换。
- 基线选 MotionBERT：Apache-2.0，原生支持 Halpe-26，输出 root-relative，离线约 10 FPS。VideoPose3D（MMPose lifter）为 CC BY-NC，只作内部研究对照，不进产品。RTMW3D 输出 COCO-WholeBody 133 点，与 Halpe-26 不兼容，等于替换整个二维前端，不选。MDVPose 没有公开权重与 license，仅在拿到 Ski-Pose PTZ 且能做微调后评估。
- 许可进入选型：产品路线不能依赖 CC BY-NC（VideoPose3D）或无 license 的权重。
- 输出统一为 root-relative。指标只用关节角与相对量；不输出世界轨迹、绝对位置或速度，单目重建有尺度歧义。
- 三维结果不改变二维管线：两者并行产出，便于回归对照。

### 相位划分

- 主信号是相对重力方向的带符号侧倾；画面横向轨迹与膝弯周期做交叉校验。
- 一个弯 = 一次完整的侧倾振荡（过零 → 极值 → 过零）。要求半周期幅值 ≥6°（换刃零点到本弯峰值）、单弯时长 ≥0.5s。首尾不完整的弯丢弃。阈值标 `TODO_VALIDATE`。
- 相位边界：换刃 = 侧倾过零；三个相位以本弯最大侧倾的 50% 为界——升到 50% 之前为入弯，50% 以上核心段为控制，回落到 50% 以下为出弯。
- 每个弯输出切分置信度（三信号边界一致性）。低置信弯的帧不进相位聚合。
- 相位聚合只覆盖屈髋、膝弯、躯干前倾三项。正面两项维持全程口径：相位概念在额状面没有可验证的定义。
- 整段找不到合格弯时，不出相位条，回退到全程数值并注明"未检测到有效弯"。这不触发质量拒绝——素材本身可用，只是没有弯。

### 参考区间

- 参考区间增加相位维度，形成"指标 × 档位 × 相位"。
- advanced：用通过三层验证的三维管线跑 EPFL 素材，按相位出 p25~p75。验证得到的角度误差上界写入带的说明，带宽不得窄于误差区间。
- novice/intermediate：没有分相位的三维数据。沿用 advanced 实测的相位相对形状套到现有占位带上，并明确标注"档位数值未校准、且为二维口径外推"。真人教练或本地采数确认前，不用于对外结论。
- 过渡期报告并列二维与三维两列，写明参考系（体固/重力/坡面）、零点、符号与 marker 方案。二维旧带不删除，但不再作为新报告的默认判断依据。
- 调研建议参考带在三维真值上重算；自采样本撑不起分档分布，advanced 带仍按"验证过的管线跑 EPFL"生成，误差上界进入口径。这一取舍记入 ADR。
- 多机位自采素材只做验证，不参与参考带统计；样本量撑不起任何一档的分布。

### 验证与采集

- 三层验证顺序：文献锚点（弯末角度落在 Bon et al. 均值 ± 2SD 内）→ 多机位真值（逐帧角度误差、跨机位一致性）→ 现有素材物理一致性（骨长恒定、脚不穿雪面、关节不反折、遮挡处不跳变）。
- 多机位采集：3 台相机起（2 台是三角化数学下限），每台与滑行方向成 30~45° 前侧、髋部高度；60~120fps，手动锁曝光/对焦/白平衡，关防抖，录制中不移动。纯正面、纯侧面、正后方不作主视角（Ostrek 2019：误差峰值，前侧最好）。
- 同步：每段开录 3 秒内拍两次手，按音频包络对齐；判据为同一相机两次拍手的偏移差 ≤ 半帧（50fps 时 10ms）。不满足整条丢弃。手机没有 genlock，长拍中途补拍手。
- 标定：ChArUco 或棋盘格，相机对 PnP 初始化后做联合 bundle adjustment；雪道体积大，A4 板不够，用大目标、分块标定或全站仪测静态参考点。采集前后各录一次；相机一旦移动即重新标定。
- 现场判据：任一时刻每个身体段至少被 2 台相机看到，否则重录。硬雪、软雪各一组；两个速度档、两个坡度；雪服保持日常状态，不为拍摄换紧身服。
- 样本量：每个条件的 run 数按目标置信区间反推（例如关节角 ±5°），不凭经验定数。
- 外部真值补充：向 EPFL 申请 Ski-Pose PTZ（22 关节、逐帧三维姿态、标注误差 23±10mm），用于交叉验证与可能的微调；不获批不影响自采主路线。
- 验收口径：within-athlete、按相机方位角分层；关节角误差中位 ≤5°、p90 ≤10°，跨机位相位中位数差 ≤3°。参考量级：OpenCap 两机 iPhone 4.5°、Pose2Sim <4°、Fasel 2017 <4.9°。不用 H36M 的 39mm 当线。

### 质量门控

- 两段门控。上传时用廉价信号预检：容器与编码、分辨率、时长，抽帧检测人物占比。分析后用三维置信度复核，代理指标从骨长残差与重投影误差中选定（待调研）。
- 任一段不通过：整份报告不出。页面显示原因与重拍建议（人物占画面高度、避免逆光、机位距离等）。
- 验证包络写进报告与文档：已验证的坡度、机位距离、分辨率、光照条件。包络外的素材由门控拒绝。

### 报告与动画

- 报告 schema 升版。指标条目增加基准标识（三维/二维），并增加 `phases` 对象；每个相位给出中位数、落带率、带内百分位、有效帧数和判断，数据不足时该相位为 null 并带原因。顶层保留全程值作对照。
- 动画数据独立导出：每帧 26 个三维关节、相位标签、逐帧指标值。root-relative、按骨长归一化，前端用 three.js 渲染。动画不含画面纹理。
- 动画页标注数据来源（真值或单目）与误差量级，避免用户把回放当成精确测量。
- 报告页：原片（打码）与骨架并排，共享时间轴、播放速度与进度；相位着色；指标叠加可开关。
- 三维不可用时按门控规则拒绝，不提供降级报告。

### Web 与产品

- 报告页提供改选人物入口：候选来自已落盘的全部人物 trc，展示带编号的候选骨架预览；改选后只重跑评估与渲染，不重跑姿态。
- 任务表持久化为 JSON，原子写（临时文件 + rename）。重启后：排队中的重新入队；运行中被中断的标为失败并允许重试；文件名、水平档、打码开关原样恢复。
- 前后对比按相位对齐，不做逐弯匹配。每一项单独判可比性：两侧都有有效相位数据才比，否则显示"无对比数据"并说明原因。相机与坡度差异写入假设说明。
- 点选选人与任务持久化不依赖指标口径，与三维迁移并行；前后对比等三维验证通过后上线。
- 人脸打码默认开启，沿用一期实现。上传视频保留期沿用一期约定。

## Testing Decisions

好测试只验证外部行为：合成骨架进，报告与动画数据出；不断言内部实现。模型推理不进单元测试，模型精度由离线验证回答。

接缝按现有结构放，优先级从高到低：

1. **评估流程（主接缝）**：沿用 `assess` 的"一次评估出齐"契约，增加三维输入路径。指标、相位、参考带、质量门控结论全部在这里测。先例是 `tests/test_assess.py`：合成侧面骨架进，断言报告结构、视角、person 透传。
2. **提升适配器（模型边界）**：测形状、坐标与置信度契约，用假模型替换真实推理。模型精度不在这里测。
3. **离线多机位工具**：标定与三角化做成纯函数，用合成相机测——已知三维点投影到两视图，三角化还原，误差在数值容差内。先例是 `tests/test_epfl.py` 的数据集适配测试。
4. **Web 工厂**：沿用 `create_app` 冒烟测试，覆盖相位条渲染、动画数据接口、拒绝路径、改选人物、重启恢复。先例是 `tests/test_web.py`。

新增的重点用例：

- 相位切分：合成侧倾振荡序列，断言弯数、边界位置、首尾丢弃、低幅丢弃、低置信弯不进聚合。
- 三维角度数学：合成直立与屈曲骨架，断言与二维口径在近平面条件下一致。
- 报告结构：相位数据不足时为 null 并带原因；全程值与相位值并存。
- 对比可比性：两侧视角/相位数据不同的矩阵，断言"不可比"的项被标出。
- 动画数据：每帧关节数、归一化方式、相位标签长度与帧数一致。

不测：真实模型精度、真视频端到端（验证阶段用脚本和报告回答）。

## Out of Scope

- 自管二维姿态模型（重写检测、跟踪、关键点层）
- 自研主轨迹评分器
- 微信小程序、账号体系
- 完整数据合规流程
- 多机位作为产品运行时输入
- 实时与端侧推理
- 综合评分制
- 膝盖内扣的临床解释与风险筛查结论（三维 JCS 定义本期落地，面向用户的"是否有内扣风险"判断需教练与临床确认后另立）
- 世界轨迹、绝对位置与速度输出（单目尺度歧义）
- 单目三维模型的训练或微调（若 Ski-Pose PTZ 获批且第一阶段验证证明必要，另立）

## Further Notes

**已由调研确定**：MotionBERT 为基线模型；采集协议见"验证与采集"；指标定义按 JCS 冻结；验收阈值采用调研量级；向 EPFL 申请 Ski-Pose PTZ。

**仍需决定**：每个条件的 run 数与滑手数（按目标置信区间反推）；髋屈曲的近端段用骨盆还是下背（ISB 是骨盆–股骨，滑雪文献常用下背–大腿近似，数值不同）；肩线与髋线用哪些 landmark；坡度角 β 的测量方法（全站仪、IMU 还是雪道图）；3 台是否够覆盖整段雪道与遮挡，还是需要 4 台；户外几十米体积的三角化真值自身精度；运行时三维置信度代理（骨长残差还是重投影误差）。

**主要风险**：

- 运动分布差距：H36M 训练的模型在 AthletePose3D 上 MPJPE 257mm，微调后约 100mm。滑雪蹲姿与高速动作落在分布缺口里，单目三维在生产素材上可能明显差于自采真值。这是迁移能否成立的核心问题。
- 单目深度歧义。修掉投影偏差的同时引入深度误差，两者谁大必须由跨机位一致性回答。
- 同步与标定是现场最大的误差源，返工成本高；标定误差会系统性进入所有三角化点，且不会被指标之间的对账发现。
- 宽松雪服与雪杖遮挡没有针对滑雪的量化数据，影响量级未知。
- 自采样本小，只能验证管线，不能支撑分档分布。
- novice/intermediate 的相位带是从 advanced 外推，水平间相位形状是否一致未经证明。
- between-athlete 的 accuracy 偏差可达 −10.7°（左髋屈曲），跨人排名不可直接比；within-athlete 的前后对比可用。
- 许可约束：VideoPose3D 为 CC BY-NC，AthletePose3D 仅限非商业科研，MDVPose 无 license；产品路线只能依赖 Apache-2.0 一类许可。
- 输出只有 root-relative；产品若要距离、速度或世界轨迹，三维迁移解决不了。
- 实拍与人工标注在关键路径上，工期依赖雪场与人力。

**顺序与依赖**：三维骨架与验证 → 指标迁移 → 相位与参考带 → 前后对比。点选选人与任务持久化并行。

**决策记录**：一期决策 #3（"单目三维明确不做"）需改写为"二维为主、三维用于动画与指标；指标迁移以三层验证为前提"；决策 #10 的放行标准需在三维口径下重写。三维六项指标的 JCS 定义与 marker 方案、参考带的取舍（验证过的管线跑 EPFL 而非三维真值重算）各需一条 ADR。四条 ADR 应在实地采集前完成，因为定义冻结是采集的前置条件。

**证据记录**：EPFL 116 个 clip 的髋部横向跨度实测（中位 0.29 画面宽）是本规格把二维读数称为"投影角"的依据；EPFL 的二维对账不能证明角度等于身体角度，原因是对账两侧都在同一图像平面。
