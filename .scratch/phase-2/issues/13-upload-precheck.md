# 13 — 上传预检门控

Status: resolved
Blocked by: None — can start immediately

## What to build

上传时用廉价信号预检：容器与编码、分辨率、时长，抽几帧测人物占比。不合格当场拒绝，给出原因与重拍建议，不进入分析队列。

## Acceptance criteria

- [x] 预检判据可配置，默认值有依据
- [x] 拒绝响应包含具体原因与重拍建议
- [x] 合格素材正常入队，预检耗时不影响上传体验
- [x] 页面能展示拒绝原因
- [x] 抽帧检测失败时按"无法判定"处理，不误杀

## Notes

来源规格：`.scratch/phase-2/spec.md`（质量门控）。

## Answer

预检逻辑在 `skibot/precheck.py`，上传接线在 `skibot/web/app.py` 与
`skibot/web/templates/upload.html`：

- `PrecheckConfig` 四项判据，默认值与依据写在类 docstring：时长
  3s~600s、帧数 ≤10000（README 的长视频建议线，帧数直接对应分析工作量）、
  分辨率短边 ≥480 / 长边 ≥720、人物高度占比 ≥0.18。人物阈值与内置 HOG
  的实际分辨力对齐：检测窗口 64x128，人高不足 128px 检不出；720p 下 128px
  等于帧高 17.8%，阈值再低这条硬门就永远触发不了。
- `run_precheck` 顺序：文件存在性 → 打开与宽高（不可解码）→ 分辨率 →
  时长/帧数。元数据已判失败就不再抽帧，省上传路径的检测时间。帧率或帧数
  读不出（VFR、索引缺失、fragmented mp4）时跳过时长判据并注明，不当拒。
- 抽帧人物占比：帧数已知按 10%~90% 比例 seek；帧数未知（VFR、索引缺失）
  时无法确定采样位置，只确认能解码、跳过人物占比判据并注明。检测用 HOG
  （原生分辨率，长边超 1920 才缩放）。检不出、检测器抛
  异常、容器不能按帧 seek 都按“无法判定”放行并在 notes 里分别写明原因；
  只有元数据可读却一帧都解不出，才按不可解码拒绝（拖到 Sports2D 阶段才
  失败就晚了）。
- 上传接线：`run_precheck` 放进线程池，不阻塞事件循环；不通过返回 422，
  `detail` 里逐条给 `check/problem/advice`，并删掉已落盘的上传文件，不进
  分析队列；通过则入队并把“无法判定”类说明放在 `precheck_notes` 返回。
  上传页把 422 的结构化原因渲染成列表（原因 + 重拍建议）。
- `skibot serve --no-precheck` 关闭预检；判据可编程覆盖
  （`create_app(precheck_config=...)`）。

测试：新增 `tests/test_precheck.py`——垃圾字节/文件缺失/分辨率/时长上下限/
多重不合格/判据与抽帧次数可配置/内置 HOG 缩放与端到端（小人物拒绝、大人物
放行）/不可解码拒绝/不能 seek 放行/帧率未知放行/采样点 10%~90%/检测器异常
与漏检分开写；`tests/test_web.py` 的 `test_upload_precheck` 覆盖合格入队、
422 结构化拒绝并清盘、判据可配置、页面展示。`mypy skibot` 无问题。

未做：预检结论写进报告与任务表（目前只在拒绝响应里）；真正的轻量人物检测
器（HOG 对滑雪蹲姿的漏检率没有量化，按“无法判定”放行兜底）。
