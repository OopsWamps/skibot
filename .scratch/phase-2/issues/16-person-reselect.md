# 16 — 报告页改选人物

Status: resolved
Blocked by: None — can start immediately

## What to build

分析完成后在报告页改选被分析的人。候选来自已落盘的全部人物轨迹，展示带编号的候选骨架预览；改选后只重跑评估与渲染，不重跑姿态。

## Acceptance criteria

- [x] 候选列表来自全部人物轨迹，不是只有自动选中的那一个
- [x] 预览带编号，能对应到人物
- [x] 改选后不重跑姿态检测
- [x] 报告与标注视频同步更新
- [x] 单人素材不出多余候选

## Notes

来源规格：`.scratch/phase-2/spec.md`（Web 与产品）。

## Answer

改选逻辑在 `skibot/reselect.py`，报告页接线在 `skibot/web/app.py` 与
`skibot/web/templates/report.html`：

- `list_candidates` 从结果目录的全部人物 px trc 生成候选（pid、有效帧数），
  单人素材也返回这一个候选，页面按数量决定是否显示选择器。
- `reselect_one` 复用已落盘轨迹重跑 `assess` + `render_annotated`，不调用
  Sports2D、不改写 trc。标注视频先渲染到临时文件并检查非空，成功后
  `os.replace` 原子替换，报告最后写——渲染失败时报告与视频都保持旧人物，
  不会出现“报告 person 1 + 视频 person 0”的错配。
- 视频源由首次分析的打码开关决定（任务表的 `blur`）：True 必须用打码副本，
  副本丢失直接报错，绝不静默改用未打码原片；False 用上传原件，即使目录里
  还留着旧副本；未传时按副本存在性推断（兼容旧任务）。`analyze_one` 在
  `--no-blur` 时删除同名旧副本。
- 编号预览：每个候选取自身离视频中点最近的有效帧（人物只出现半段时不会
  画出空骨架），画该轨迹的骨架并标 `person N`，写
  `candidate_person<pid>.jpg` 经 `/files` 展示；人数变少时清理幽灵预览；
  零有效帧或读帧失败跳过，不阻塞改选。
- Web：`GET /api/tasks/{id}/candidates` 返回当前人物与候选（含预览地址）；
  `POST /api/tasks/{id}/person` 校验人物存在后丢后台线程跑改选，立即返回，
  同一任务同时只允许一个改选（409）；`GET /api/tasks/{id}` 带
  `reselecting`/`reselect_error`，报告页轮询结束后自动刷新。报告页对多人
  素材显示候选骨架 + 编号按钮，单人素材不显示。

测试：新增 `tests/test_reselect.py`——候选来自全部轨迹、单人不出多余候选、
改选重跑并原地覆盖、越界拒绝、沿用原视频标签、编号预览、预览骨架与人物
一一对应、部分轨迹取最近有效帧、不重跑姿态（trc 逐字节不变）、打码副本
优先/显式 blur/副本丢失报错、渲染失败不更新报告、幽灵预览清理；
`tests/test_web.py` 的 `test_web_reselect` 覆盖候选接口、报告页渲染、异步
改选后报告与视频更新、越界与未完成拒绝。`mypy skibot` 无问题。

未做：改选历史（只保留最后一次）；候选缩略图批量拼接。

## Comments

2026-10-23：独立验证工作流确认 6 处，已修：

- 打码副本优先逻辑无测试 → 增加 blurred/fallback/显式 blur/副本丢失四分支。
- 预览只断言文件存在 → 记录每张预览收到的骨架，断言候选与人物一一对应。
- 「不重跑姿态检测」无直接断言 → 改选前后对 trc 做 sha256 快照比对。
- 预览固定取中点，人物只在半段出现时预览没有骨架 → 逐候选取最近有效帧。
- 先写报告后渲染，渲染失败（Windows 文件锁）留下报告/视频错配 → 先渲染到
  临时文件、成功后替换，报告最后写；`render_annotated` 检查 writer.isOpened。
- 打码设置靠副本存在性推断，`--no-blur` 复用目录时用旧副本 → 显式传 blur，
  `analyze_one` 在未打码时删除旧副本；副本丢失时报错。
